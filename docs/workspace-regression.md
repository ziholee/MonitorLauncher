# 워크스페이스 회귀 검증

실행 환경: Windows, .NET 8 SDK, 모니터 2대. 아래 항목은 수동 검증 절차이며 현재 macOS 환경에서는 실행하지 않았다.

먼저 `dotnet build MonitorLauncher.csproj -c Release`를 실행한다.

| 항목 | 재현 절차 | 기대 결과 |
| --- | --- | --- |
| 단일 앱 회귀 | 기존 프로필 저장, 실행, 삭제 및 트레이 실행 | 기존 모니터 선택과 창 상태 설정 유지 |
| 같은 앱 여러 창 | 제목이 다른 메모장 창 2개를 다른 위치에 저장하고 이동 후 복원 | 각 창이 한 번씩 저장 위치로 복원 |
| 프로세스 경로 | 이름은 같고 경로가 다른 실행 파일의 창을 열고 하나만 저장 | 다른 경로의 창을 이동하지 않음 |
| 모니터 빈 공간 | 디스플레이를 대각선 배치하고 창을 실제 화면이 없는 틈으로 이동 후 복구 | 주 모니터 작업 영역 안으로 이동 |
| 정상 창 유지 | 접근 가능한 일반 창을 보조 모니터에 둔 뒤 화면 밖 창 복구 | 정상 창은 이동하지 않음 |
| 모니터 제거 | 보조 모니터에 배치를 저장하고 연결 해제 후 복원 | 주 모니터 안으로 복원, 대체 수와 안내 표시 |
| 해상도 감소 | 저장한 모니터의 해상도를 낮춘 후 복원 | 창 크기와 좌표가 현재 작업 영역 안으로 제한 |
| 이동 실패 | 디버거로 창 선택 직후 중단하고 대상 창 종료 후 계속 | 해당 창은 성공 수에 포함되지 않고 실패 안내 |
| 캡처 필터 | 탐색기 및 Terminal을 열고 현재 배치 가져오기 | 두 앱은 목록에 포함, 바탕화면과 작업 표시줄 제외 |
| 중복 실행 | 종료된 앱의 복원을 시작하고 대기 중 트레이 메뉴 확인 | 워크스페이스 메뉴 비활성화, 완료 후 활성화 |
| 덮어쓰기 취소 | 기존 이름으로 다른 배치를 저장하고 아니요 선택 | 파일과 기존 배치 유지 |
| 덮어쓰기 승인 | 같은 과정에서 예 선택 | 새 배치 저장 및 해당 항목 선택 |
| 작은 화면 | 1366x768 및 150% 배율에서 실행하고 창 크기 축소 | 스크롤로 저장, 복원, 삭제, 상태 표시 접근 가능 |

동일하거나 변경된 창 제목은 앱 내부의 문서 식별자가 아니므로 대응 순서를 보장하지 않는다. 앱의 단일 인스턴스 정책 때문에 새 창이 생성되지 않으면 기존 창을 중복 이동하지 않고 실패로 보고한다.
